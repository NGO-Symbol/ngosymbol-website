# ADR-0010: One image pipeline with a guard

- Status: Accepted
- Date: 2026-11-06
- Supersedes: the `sips`-based AVIF previews of 2026-10-30 (`make-previews.mjs`, `public/media/previews`, `thumbs`)

## Context

The sites are static (GitHub Pages, no server, no CMS). Photographs are added by non-developers working through AI agents, so the rule «optimise before you add» cannot rest on memory or discipline. Before this change `apps/main/public/media` held about 207 MB of JPEG originals (up to 2000 px, 0.5-1.4 MB each) plus a macOS-only preview set (`sips`, 960 px AVIF) that had to be regenerated by hand and that a new photograph silently skipped. Components had no `width`/`height`, `srcset` or placeholders.

The sister project «WBM band website» solves the same problem with a preset file (`constants/imagePresets.json`), `sharp` writing AVIF/WebP/JPEG at several widths per preset into a committed `optimized/` folder, a `<ProgressiveImage>` component (`<picture>` + `srcset`), and a skill telling agents to run `npm run compress-images`. It has no check: nothing fails when someone forgets, and every image needs a preset and a hand-built path.

## Decision

1. **`scripts/optimize-images.mjs` (sharp), committed outputs.** For each photograph in the managed folders (`apps/main/public/media`, `apps/documents/public/works`):
   - the file keeps its path and becomes the *web master*: `.jpg`, long side ≤ 1600 px, mozjpeg, sRGB, EXIF (including location) stripped, ≤ 400 KB;
   - AVIF variants at 480, 960 and 1600 px (never upscaled) are written to `_opt/` beside the folder root (`/media/a/b.jpg` → `/media/_opt/a/b-960.avif`).
   The data model is unchanged: `Photo.src` stays `/media/…/name.jpg`.
2. **Manifest.** `apps/main/app/data/images.json` holds width, height, average colour and variant widths per photograph; `images.lock.json` holds the hash of each master. Output is deterministic and idempotent.
3. **One component.** `<MediaImg>` (main and exhibition site) renders a single `<img>` with `srcset` of the AVIF variants, `sizes`, intrinsic `width`/`height` (no layout shift), the average colour as a placeholder, `loading="lazy"` (`priority` gives eager + `fetchpriority="high"`), and falls back to the master JPEG if the browser cannot open AVIF. It stays one element so existing scoped image styles keep working; there is no page CSS.
4. **Guard against bypass.** `pnpm images:check` (part of `pnpm check`, therefore CI and `task:ship`) fails when a photograph is not `.jpg`, is over the budget or 1600 px, still has EXIF, is not recorded in the lock with the same hash (never processed, or edited afterwards), has missing/orphan variants, is missing in the manifest, has a bad file name, or when app code points at a path that is not a processed photograph (including the retired `previews`/`thumbs`). `pnpm task:save` runs the optimizer before committing, so the normal path needs no thought. The skill `add-photo` tells agents the exact steps. Logos (`media/partners`, `press-kit`) are graphics: PNG/SVG only, ≤ 250 KB, losslessly re-compressed.
5. **Originals stay out of the repository.** The team's originals live in `media-inbox/` (local, already in AGENTS.md). Git keeps only masters and variants.

## Alternatives considered

- **`@nuxt/image` at build time** (IPX/sharp during `generate`). Rejected: derivatives are produced in CI at every build (slower builds, nondeterministic across versions), nothing guards the source folder (a 6 MB original still gets committed and deployed), the GitHub Pages bundle needs extra config for the static provider, and it works only through its own `<NuxtImg>` while photos are plain strings in data files.
- **WBM-style presets with `<picture>` AVIF/WebP/JPEG.** Rejected for this site: three formats triple the committed files for a browser share that no longer needs WebP; per-folder presets and extension-less paths are another thing for agents to get wrong. We keep its good parts (sharp, committed outputs, one config, a skill).
- **Blurhash / LQIP data URIs.** Rejected: needs a decoder in JS or a base64 string per photo in the bundle. The average colour (7 bytes) removes the white flash, and AVIF at 480 px is already tiny.
- **Keeping originals in git/LFS.** Rejected: the 217 MB of originals were the repository's size problem; history is not rewritten, but new weight stops growing.

## Consequences

- Adding a photograph = copy the file, `pnpm task:save`. Forgetting is not possible on the normal path and fails CI on any other.
- The optimizer re-encodes once; masters are not re-encoded again (hash match). Changing the policy (quality, widths) means deleting `images.lock.json` and re-running, which re-encodes from the already-compressed masters; keep the originals in `media-inbox/` for that.
- Browsers without AVIF (very few) get the master JPEG through the `error` fallback, but only after hydration.
- `git` history still contains the old originals; only new weight stops growing.
